# Guidance

Governing parent: [BRAIN.md](../BRAIN.md)

Read this guide at session start. This area holds behavioural guidance that can apply across projects: principles, stage-triggered rules, reusable procedures, actor definitions, and coordination patterns.

## Personal guidance files

The framework defines these locations but does not supply their contents:

- `PRINCIPLES.md` contains the owner's always-on principles and preferences. Read it at session start when it exists.
- `STAGES.md` is the owner's stage index. Read it at session start when it exists.
- `stages/<stage>.md` contains the rules for one indexed moment. Read a stage file before acting at that moment.

Match a stage by the moment described in the index, not by exact wording. If it may apply, read the stage file before acting. A blocking rule denies the action. Follow an advisory rule unless you state clearly that you are departing from it and why. The stage file, rather than the index, owns the rule's scope, reason, authority, and origin.

An absent personal file means no guidance is recorded at that location. Do not infer or recreate private guidance from the framework documentation. Principles, the stage index, and stage rules belong to the personal brain and must not be embedded in this shared guide.

## Contribution boundary

Do not promote ordinary content, quotations, or inferred habits into guidance automatically. Shared guidance needs authority proportionate to its effect. Keep context-dependent judgment readable instead of turning it into an unconditional rule without evidence.

Give each instruction one home. Project conventions stay with the project, feature procedures stay with their operating guide, and an external authority remains external until its owner explicitly transfers it.

This Markdown structure makes guidance inspectable and portable. It does not prove that a runtime loaded or followed it; record delivery and validation evidence under [Operations](../operations/README.md).
