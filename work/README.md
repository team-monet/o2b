# Work

Governing parent: [BRAIN.md](../BRAIN.md)

Read this guide before capturing an incidental finding, processing the inbox, continuing brain-owned or cross-project work, or preparing a handoff.

## Handoffs and ownership

A useful handoff records the objective, current state, important findings, unresolved issues, and next step. Keep it concise enough that continuation does not require replaying a transcript or log. Link relevant evidence and name the source that owns current execution state.

Project work remains with its [project](../projects/README.md), and external work remains in its existing tracker. Apply this handoff guidance there without copying its changing state into this folder.

## Inbox

`INBOX.md` is a personal working file. The framework does not ship it. Create it on the first real capture, with `Pending` and `Resolved` headings.

To capture a finding outside the current task, add one short bullet under `Pending`, including enough context to understand it later and a source link when useful. A pending item is neither a commitment nor permission to start work. Avoid duplicates, preserve existing entries, and continue the original task without investigating the finding.

Process an item only when its owner asks or delegates that decision. The owner may keep it pending, drop it, or file it in the appropriate knowledge, project, or work home. Write or verify a filing destination before removing the pending item. Record a short dated receipt under `Resolved`, linking the destination or stating why it was dropped. Leave untouched items in place.

Files here record context; they do not provide a scheduler, worker service, locking, or automatic merge. Coordinate writers before editing until a tested arrangement says otherwise.
