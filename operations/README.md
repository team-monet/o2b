## Records and evidence

An operational record identifies the real mechanism, configuration scope, known limits, and a dated or version-bound validation result. A folder, instruction, or intended design is not evidence that a control exists.

For access and privacy, name the technical boundary that prevents exposure. Refer to credential configuration without copying secrets. For backup and recovery, record recoverable scope and restoration evidence. For multiple writers, cover both overlapping text changes and semantic conflicts. For each runtime, record how applicable guidance reaches the actor before action and how delivery was checked.

Indexes, caches, embeddings, graphs, and context preparation remain replaceable. They cannot be the sole home of durable truth. Record how canonical corrections and removals propagate and how rebuilds avoid returning removed material to active use.

Test destructive recovery, corruption handling, privacy boundaries, and secret handling only with isolated fixtures.
